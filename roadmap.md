# The Website Factory Roadmap

**Strategic Direction:** Operate a web agency with an internal, reusable production system. The agency storefront is the default output; the workshop is a separate internal preview. Prioritize completing the brief-to-handover cycle with real projects and measuring where reuse helps before expanding the library. See [the agency workflow](docs/agency-workflow.md).

**Current interface step:** A functional low-fidelity project workspace supports saved briefs, page plans, editable section copy, reordering, human review, exported design handoffs, and direct plan-to-preset compilation into verified factory presets (`scripts/from_plan.py`). Claude can draft plans from a brief (`scripts/draft_plan.py`), and agents can drive the factory through its MCP server (`scripts/mcp_server.py`). The existing component catalog is supporting reference at `/site-kit/catalog/`.

**Completed Milestones & History:** All completed milestones (Milestones 1–14) and historical release notes have been moved to [CHANGELOGS.md](CHANGELOGS.md).

**Current Baseline (2026-11-18):**
- **Architecture & Build:** Pinned Hugo Extended 0.166.0 + Dart Sass 1.104.1 via Hugo Pipes (`@use`, css.Sass, `hugo:vars`), both installed privately into `.tools/` via `scripts/setup.py` with SHA-256 verification and a shared per-user hardlink cache (`~/.cache/website-factory`) so system upgrades cannot break pinned builds. System-independent Python build helper (`scripts/build.py`) with preflight output reconciliation protecting untracked static assets (`.html`, `.js`, `.css`, `.map`), canonical sibling output locking (`scripts/output_lock.py`), build receipts (`.factory-receipt.json`), release ID tracking (`factory-release.json`), crash-resilient manifest recording, and production-like local serving (`--serve` sends built `_headers` including CSP and serves the site's 404 page). Five self-hosted, open-licensed font pairings (`data/fonts.json`) with uniform `OFL-<name>.txt` license validation and a 90 KB preload budget. Optional `short_name` in `data/site.yaml` keeps `<title>` tags under 60 characters for long business names. Configurable search-engine visibility (`hugo.toml` `params.noindex`, `HUGO_PARAMS_NOINDEX` env var). Python floor elevated to 3.11+ for native TOML parsing (`tomllib`). Pinned CI runner on `ubuntu-24.04` with all GitHub Actions pinned to exact commit hashes and concurrency group protection in `.github/workflows/deploy.yml` ensuring in-flight `workflow_dispatch` releases are never cancelled by branch pushes.
- **Hosting & Forms:** Cloudflare Pages default (`wrangler.toml` with `ENQUIRY_ENABLED = "false"` safe default) with `static/_routes.json` scoping Pages Functions strictly to `/api/*` and top-level dotfiles (`/.*`), and same-origin Pages Function (`functions/api/contact.js`) for durable enquiry storage in Cloudflare KV (`ENQUIRY`) with 90-day data retention TTL (`expirationTtl`), client IP rate limiting (best-effort 5 submissions per 10 minutes, salted with `RATE_LIMIT_SALT` secret to prevent IP hash reversal), 64 KB streamed payload byte counting with web-standard `Blob` multipart parsing, optional `NOTIFICATION_WEBHOOK` forwarding with HTTP response validation (`res.ok`), explicit per-deployment intake gating (`ENQUIRY_ENABLED = "true"`), durable storage-first acknowledgment (502 on storage failure; best-effort webhook notification once stored), and strict security headers on all function responses. Enquiry CLI (`scripts/enquiries.py`) supports listing, CSV/JSON export, privacy-safe monthly/type summaries (`summary`), and confirmed visitor deletion requests (`delete --email`). Live care-plan check (`./wf care`, `scripts/care.py`) runs read-only smoke checks plus TLS certificate expiry, HTTP-to-HTTPS redirect, and response-time checks across `care-sites.txt`. Other hosts can use an outside `https://` form service through `params.formAction`, or set `contact_mode` (`inquiry`, `email`, `link`, `off`).

## Active & Planned Priorities

### Open
- **First live AI runs:** record real drafts for the plumber and food-bank test briefs (`scripts/eval_plans.py --live --record`) and review the scores.
- **Live studio site is behind `main`:** `258webco.com` serves no `factory-release.json`, so its release predates 2026-10-03 (pricing and identity changes since then are not live). All 17 `./wf care` checks pass on it. Redeploying is owner-authorized only.
- **Confirm the Functions routes on a preview:** `static/_routes.json` now limits Functions to `/api/*` and dotfiles. Run the preview workflow once; its new smoke step must show the build inventory still answers 404 before the next production release.
- **Home page search title (review M4):** the live title is "Home — 258 Web Co.". Set `pages.home.seo_title` in the `258webco` preset once the wording is confirmed.
- **Cloudflare Workers hosting evaluation (`docs/plan-workers-hosting.md`):** evaluate moving from Pages to Workers with static assets + `send_email` bindings for transactional enquiry emailing without an outside mail vendor. Draft plan recorded for owner decision.

### Decided against for now
- **R2 media hosting for client sites (2026-10-14):** images ship with the site on Pages. R2 would need a security-policy, output-check and validation change; revisit only when a client needs files over 25 MiB or 20,000 files. See `docs/guide-to-hosting-on-cloudflare-on-the-cheap.md`.
- **Live preview inside the planner:** it would need a page embedded in a page, which the site's `frame-ancestors 'none'` security rule forbids. The planner links to each module's catalog entry instead.
- **Cloud saving for the planner:** the planner stays a browser tool with JSON export and import; saving elsewhere would need an account and a server, which the static-site boundary excludes.

## Explicit Boundaries & Non-Goals

- **No Runtime CMS or Database Requirements:** The factory remains strictly static Hugo; content and composition are managed via version-controlled Markdown, YAML, and JSON.
- **No Client-Side Framework Overhead:** Components must use standard HTML5 semantic elements and modern CSS. JavaScript is reserved for progressive enhancements (such as form submission feedback) and is never required for core navigation or reading.
- **No Fabricated Performance or Legal Claims:** Default presets, sample case studies, pricing tables, and testimonials are explicitly labeled as fictional. Client copies do not inherit historical test scores or delivery guarantees.
